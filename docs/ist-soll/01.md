## Sicherheitsauffälligkeiten

1. **Block-Filter durch spätere Policies ausgehebelt.** PostgreSQL verknüpft permissive Policies mit OR. Migration 002 filtert blockierte Nutzer konsequent, aber:
   - `003_routing_functions.sql:206-208` `"Published and curated routes are publicly readable"` `USING (is_published OR is_curated OR auth.uid() = user_id)` – ohne `is_blocked`, hebelt `routes_select` (`002:316-322`) aus.
   - `007_gamification_stats_premium.sql:383-384` `user_badges_read_public USING (TRUE)` – hebelt `user_badges_select` (`002:787`, mit Block-Filter) aus.
   - `007:393-394` `challenge_participants_read USING (TRUE)` – jede Person sieht alle Teilnahmen.
   - `007:388-389` `challenges_read_active USING (TRUE)` – harmlos, aber Name irreführend (kein Datumsfilter).
   Die Spezifikation (1.6, Hinweis) verlangt: "Blockierte Nutzer müssen in allen SELECT-Policies berücksichtigt werden."
2. **`users` liefert sensible Spalten an alle.** `users_select` (`002:105-118`) ist zeilenbasiert; damit sind `email`, `push_token` und `notification_prefs` jedes öffentlichen Profils für jeden Leser abrufbar – auch für nicht angemeldete (anon) Clients, weil `auth.uid() IS NULL` die Bedingung `NOT is_private` nicht blockiert und `is_blocked(NULL, id)` `false` liefert. Genau das soll die View `public_profiles` aus Anhang A lösen; zusätzlich sollte `SELECT` auf `users` für `anon` entzogen werden.
3. **`SECURITY DEFINER`-Funktionen ohne `SET search_path`.** `is_blocked`, `is_following`, `is_mutual_follow`, `is_group_member`, `is_community_member` (`002:44-96`) laufen als Definer ohne festgelegten Suchpfad; Supabase empfiehlt `SET search_path = public` (bzw. leer) gegen Search-Path-Angriffe.
4. **`reports` ohne UPDATE/DELETE-Policy, aber auch ohne Moderations-Rolle** (`002:752-762`): Auflösung soll über Service-Role laufen, eine entsprechende Edge Function fehlt (nicht Teil von Dokument 01, aber Hinweis).
5. **Uploads ohne serverseitige Validierung.** `lib/storage.ts:22-51` schreibt direkt vom Client in Supabase Storage mit `upsert: true`. Ohne Storage-Policies (keine in den Migrationen gefunden) können Nutzer fremde Pfade überschreiben; Dateityp/-grösse wird nicht geprüft. Die Spezifikation verlangt eine validierende Edge Function.
