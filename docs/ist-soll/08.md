## Sicherheitsauffälligkeiten

1. **Jeder Nutzer kann sich selbst Premium geben.** `users_update` (`002_rls_policies.sql:126-130`) erlaubt `UPDATE` auf die eigene Zeile ohne Spaltenbeschränkung; es gibt keinen Trigger, keine Spalten-Grants und keine `REVOKE`-Anweisung (grep `REVOKE\|GRANT\|OLD.is_premium` in `supabase/`: 0 Treffer). Ein `PATCH /rest/v1/users?id=eq.<uid>` mit `{"is_premium": true}` (oder `is_verified: true`) genügt. Die App selbst nutzt genau diesen Weg (`app/premium.tsx:33-36`). Alle Premium-Gates sind damit nur kosmetisch.
2. **`award_badge` ist SECURITY DEFINER und für alle authentifizierten Nutzer aufrufbar** (`007:70-93`, Parameter `p_user_id`, `p_badge_id`): Jeder kann sich oder anderen beliebige Abzeichen (inkl. `early_adopter`, `summit_4000`) geben und dabei Notifications an fremde Nutzer erzeugen. *Erledigt 25.10. (Migration 024, PR #41): nur noch für das eigene Konto; sich selbst kann man weiterhin jedes Abzeichen geben, bis die Vergabe serverseitig läuft (Aufgabe 3).*
3. **`update_challenge_progress` ist SECURITY DEFINER mit frei wählbarem `p_progress`** (`007:214-260`); zusätzlich erlaubt `challenge_participants_update` (`002:835-839`, `007:400-402`) das direkte Setzen von `progress`. Ranglisten sind manipulierbar. *Erledigt 25.10. (Migration 024, PR #41).*
4. **`get_user_stats`, `get_monthly_activity`, `get_personal_records` sind SECURITY DEFINER mit beliebiger `p_user_id`** (`007:98-210`): Statistiken privater Profile und geblockter Nutzer sind für jeden abrufbar (umgeht `recordings`-RLS und `is_private`).
5. **`get_live_tracking_by_token`** (`007:300-330`) liefert Standort, Anzeigename und Avatar an jeden, der den Token kennt – gewollt, aber der Token entsteht aus `Math.random()` (`useLiveTracking.ts:36-39`), nicht aus einem CSPRNG.
6. **`notifications`-Trigger laufen als SECURITY DEFINER ohne Preference-Prüfung**; in Kombination mit Punkt 2 können fremde Nutzer mit Benachrichtigungen geflutet werden.
7. **Dev-Backdoor im Login** (`app/(auth)/login.tsx:107-127`): sichtbarer Button in jedem Build, setzt lokal eine Fake-Session mit Premium. Kein Backend-Zugriff, aber im Release-Build unerwünscht.
8. **`user_badges_read_public USING (TRUE)`** (`007:382-384`) hebelt den Block-Filter aus `002:796-798` aus (bereits in Dokument 01 vermerkt).

## Empfohlene Aufgaben für Agents
